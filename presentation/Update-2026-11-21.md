# A Datapoint 2200 resurrects - from IKEA kit to running - was it the first personal computer?

Abstract:

The Datapoint 2200 was created by the company CTC in the late 1960s. Was it a personal computer or an just an intelligent terminal? Fast forward to 2023 when I start my journey to resurrect a 2200 that I received a as an IKEA kit into a working machine. A journey that includes creating a simulator, digitzing cassette tapes with software, designing extender boards, creating tools to write digitized tape images back to cassettes and eventually getting the machine running.

# Datapoint a brief background

Founders - the photo - 1968
Named CTC - Computer Terminal Corporation 
Set out to build computer terminals that could replace the noisy Teletype ASR33

Proliferation of small dynamic shift registers was key which made CRTs for display viable.
Picture of shift register => Picture of CTC 3300 (33nn came from ASR33)

Shift register fit linear process of CRT scanning very well since they are purely sequential.

# Datapoint 2200

But how to interface with as many variants of host computers as possible? 

Picture of logos for all the big vendors IBM, Sperry, Burroughs, RCA, DEC, HP, GE 

Not make one hard coded terminal per type of host but make it programmable. Data entry was a big thing. Data was often entered on cards and the card were then processed by the main frame. Data entry on IBM 029

Created a small simple 8 bit computer that would fit on the desktop and could solve all communictaion and data entry tasks.

First 2200 also used shift registers as main memory and had a serial architecture where bits were shifted into the ALU and back to registers and to memory. Very slow.

On the market from 1971

# Intel 

CTC asked Intel and Texas if they could produce a chip that had the same architecture. Both tried to come up with a design but CTC thougt it was too slow.

Intel then got the right to continue to work on the chip and started to market it in 1972 - The 8008 - picture.

CTC reworked their design and made the the version II 2200 parallell with 8 bit data paths instead of serial. It is a parallell Datapoint 2200 I have here.

The 8008 then evolved in to 8080, 8086 and 80386, Pentium to the latest Intel x86 CPUs we have to day.

They still share the same foundation while the 8008 (and Datapoint 2200) is 8 bit and the modern x86 is 64 bit

# First Personal Computer ?

After a while CTC managers recognized that some customer wrote their own programs for the Datapoint 2200. Datapoint already had a small operating system with an editor and assembler suite and the machine had two cassette drives so it was possible to develop software on it. When it was created the notion of personal computer was not existing. Computers were big remote systems connected with terminals. Some terminals were more dumb than others and some very really intelligent...

Chicken farm.

Several others were working in the same field at the same time. Intelligent terminals. Incoterm, Cogar, Sycor. The Incoterm SPD 10/20 came with floppy drives and a simple operating system. So did the Cogar C4 as well.

But what is the definition of a personal computer? If one think of a tool that could be used in a regular office the Datapoint 2200 is a reasonable contender to the title.

# Actual debugging

Late 2025 I finally got to the point I could start debug it. The machine is very simple so there is no ROM in it. The boot process is controlled by logic that simply reads a full block into memory form address 0 and at the end of the block it. 

It was able to read the full tape but there were no printout on the screen. Attaching the logic analyzer at various points in the machine made it possible to track down the problem.

Did the really read the contents of the tape correctly ? - Yes it did.
Was it written into memory - Yes it was.
Was it executing instructions correctly. Yes it at least started.

By comparing with the simulator I found a certain instruction that behaved differently.

From studying the schematic and when I know what instruction that failed it was quite clear that it could only be one chip that was the problem which was confirmed by the logic analyzer.

A 7404 was broken.

# Running!

I ran through many of the diagnostics and the memory test revealed a number of memory chips that were flakey.

But after this it was stable!
